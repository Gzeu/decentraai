# DecentraAI

Decentralized P2P distribution of AI model artifacts and verifiable local or remote inference.
Nodes discover each other on the LAN, exchange cryptographically verified model chunks,
and (soon) serve inference through a local OpenAI-compatible endpoint.

## What exists today

| Milestone | Scope | Status |
|---|---|---|
| M0 | Rust workspace, CI quality gates (fmt, clippy -D warnings, tests, audit, secret scan) | Done |
| M1 | System probe + admission checks (`decentraai doctor`), Ed25519 identity with PeerId | Done |
| M2 | Local GGUF registry: scan/list with path safety, symlink rejection, deterministic JSON persistence | Done |
| M3 | LAN swarm: signed protocol messages, Merkle manifests, libp2p transport, verified chunk transfer with resume, end-to-end two-node tests | Done |
| M4 | Inference runtime (llama-server + OpenAI-compatible API) | Planned — see below |
| M5 | Swarm intelligence (scheduler, reputation, multi-provider downloads) | Planned |
| M6 | Hardening (quarantine workflow, audit logging, packaging) | Planned |

## Milestone details

### M3: LAN swarm ✅
- **Identity**: Ed25519 keypair generated by `decentraai init`, stored at `<data_dir>/identity/key.pem` with 0600 permissions; PeerId = `blake3(public_key)` hex; sign/verify API
- **Protocol** (`crates/protocol`): ManifestAnnouncement, ManifestRequest/Response, ChunkRequest/Response; `deny_unknown_fields`, size caps, base64 binary fields; canonical signing over compact JSON (`sign_manifest` / `verify_manifest_signature`)
- **Manifests** (`crates/manifest`): GGUF magic validation, 4 MiB chunks, per-chunk BLAKE3, deterministic Merkle root, atomic JSON writes
- **Transport** (`crates/p2p`): TCP + Noise + Yamux, mDNS discovery, length-delimited request/response frames; the swarm runs as an actor behind a command channel; libp2p keypair derived from the node identity
- **Transfer engine** (`crates/p2p/transfer.rs`): manifest fetch, per-chunk BLAKE3 verification, `.part` staging + `.done` resume bitmap, full-file hash + Merkle root gate, atomic rename into `models/`
- **End-to-end tests**: two real nodes on loopback — byte-identical download, corrupted-chunk rejection, resume requesting only missing chunks

### M2: Local model discovery ✅
- Supported formats: `.gguf` only (matches the verification capability of decentraai-manifest)
- Safety: path validation, canonicalization, symlink rejection, idempotent scans, atomic registry saves

### M1: Foundation ✅
- `decentraai doctor`: CPU/RAM/disk budget derivation, NVIDIA GPU probe (name, free VRAM, temperature), inference admission verdict (admit/reject with reason)
- Strongly typed config: enums for `gpu_enabled`, `inference.enabled`, `inference.runtime`, `security.trust_mode` — typos fail at parse time

## Where we are going: M4 — inference runtime

The config already anticipates the design: `inference.runtime: llama_server` means llama.cpp
runs as a **managed subprocess** (`llama-server`), not FFI bindings. Upgrade-friendly, and a
crash in inference never takes the node down.

### M4a — llama-server process manager
- New crate `decentraai-runtime`: locate the binary, spawn with args derived from config
  (`--ctx-size` from `max_context_tokens`, `--parallel` from `max_concurrent_requests`, ephemeral port)
- Health-check on `/health` until ready; kill on drop (no orphans)
- Model name to path resolution through the existing `ModelRegistry`
- Tests use a fake binary (shell script mimicking llama-server) — no GPU needed in CI

### M4b — admission gate
- `SystemSnapshot::collect()` + `admit_inference()` before every model load
- `InferenceMode::{Auto, Always, Never}` honored; GPU temperature limit from `stop_gpu_temperature_celsius`
- Idle unload after `idle_model_unload_minutes`

### M4c — OpenAI-compatible endpoint + CLI
- Thin axum proxy on `inference.bind_address`: `/v1/chat/completions`, `/v1/completions`, `/v1/models`
- Local auth token when `api_auth_required: true` (generated at `init`)
- CLI: `decentraai serve start --model <name>`, `serve status`, `serve stop`
- E2E test: registry with a fake GGUF, serve start, HTTP request round-trip

### M5 / M6 (after M4)
- **M5 swarm intelligence**: deterministic task scheduler, peer reputation scoring, multi-provider downloads
- **M6 hardening**: quarantine workflow for corrupted artifacts, audit logging and metrics, packaging guide

## CLI quick reference

```bash
decentraai init --data-dir ~/.decentraai        # bootstrap dirs + Ed25519 identity
decentraai doctor --config <path>               # budgets, GPU, PeerId, admission verdict
decentraai config validate --file <path>        # strict config check
decentraai registry scan --directory <path>     # index local GGUF models
decentraai registry list                        # show registered models
decentraai swarm start --config <path>          # join the LAN swarm (libp2p + mDNS)
```

## Layout

- `crates/config` — typed YAML configuration with validation
- `crates/identity` — Ed25519 keypairs and PeerId derivation
- `crates/manifest` — GGUF manifests: chunk hashes, Merkle root, atomic writes
- `crates/protocol` — swarm message schemas and canonical signing
- `crates/p2p` — libp2p transport actor and verified transfer engine
- `crates/registry` — local model registry with path safety
- `crates/system-probe` — hardware probing and admission decisions
- `crates/node-cli` — the `decentraai` binary
- `action-plan.md`, `ROADMAP.md`, `docs/` — design and handoff documents

## Security baseline

No artifact is usable before hash, manifest, and policy verification. Manifest and chunk
responses carry no signatures by design: integrity is anchored in the signed manifest's
`chunk_hashes` and Merkle root, enforced by per-chunk BLAKE3 verification at assembly.
Prompts and outputs are never logged by default. Private keys never enter Git or telemetry.
